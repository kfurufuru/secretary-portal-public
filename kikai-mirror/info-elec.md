# 情報・電子回路

論理回路・順序回路・A/D 変換・進数に加え、BASIC と C の2言語で併記されるプログラム問題の読み方までを扱う。出題範囲は浅く広い。

**出題頻度（編集部集計）:** 中（10年で約10問・5%）

## 1.論理回路の基本

AND・OR・NOT を基本素子とし、NAND・NOR・XOR が応用される。**ド・モルガンの定理** $\overline{A+B}=\bar A\bar B$ は頻出。
覚えるべき恒等式
$A + AB = A,\quad A + \bar A B = A + B,\quad A(A+B)=A$
図3.2.1 基本ゲートの記号。出力側の小さな丸（バブル）が「否定」を表し、AND にバブルが付けば NAND、OR に付けば NOR になる。ド・モルガンの定理は「全体のバーを各文字に配ると、＋ と · が入れ替わる」と読むと機械的に使える。

## 2.順序回路（フリップフロップ）

- **RS-FF** — 基本形（NOR 形・正論理入力）では R=1, S=1 が禁止入力（両出力が同じ値になり、次の状態が決まらない）
- **D-FF** — クロックのエッジで D 入力を取り込んで保持する。**立上りか立下りかは素子で決まる**（記号のクロック端子に丸が付いていれば立下り）
- **JK-FF** — J=K=1 で反転動作。**禁止入力がない**のが RS-FF との違い

禁止入力は「形」で変わる
「RS-FF の禁止入力は R=S=1」は **NOR 形（正論理入力）の場合**。NAND 形（負論理入力）では両入力を 0 にしたときが禁止になる。問題文の回路がどちらの形かを見てから答える。

## 3.A/D・D/A 変換

分解能 n ビットのA/D変換器は $2^n$ 段階で量子化する。逐次比較形・並列比較形・積分形が主要方式。

## 4.基数変換（2進・10進・16進）

10進→2進は「2で割った余りを下位から並べる」。2進→16進は「**4桁ずつ区切って**読み替える」。逆方向（2進→10進）は各桁の重み（…, 8, 4, 2, 1）を足す。
例題 — 基数変換
**問:** (45)₁₀ を2進数と16進数で表せ。
**解:** 45 = 32 + 8 + 4 + 1 = **(101101)₂**。4桁ずつ区切って 0010 1101 → **(2D)₁₆**。検算: 2×16 + 13 = 45 ✓

## 6.プログラム問題の読み方（BASIC・C の2言語併記）

試験のプログラム問題は、同一の処理が **BASIC（JIS X 3003）**と **C 言語（JIS X 3010）**の2通りの表記で併記される（受験案内の記載として受け取ったもの。自分が受ける回の受験案内で確認すること）。2つの言語で**別々の問題が出るのではない**。同じ1つのプログラムが2つの書き方で並んでいるだけである。
結論 — 両方覚える必要はない
どちらか片方が読めれば解答できる。自分の言語を1つ決めて固定し、もう片方の表記は読み飛ばしてよい。本ページの以降の節も「片方＋対照表」で完結するように書いてある。片方で答えを出したあと、もう片方を検算に使うのは自由だが、義務ではない。
どちらを選ぶかの目安は次のとおり。
- **プログラミング経験がない** — BASIC。英単語（IF・FOR・PRINT）をほぼそのまま読み下せて、記号が少ない
- **C・Java・Python などの経験がある** — C。見慣れた記法（`==`・`{ }`・`i++`）のままでよい
- 一度決めたら**過去問演習も同じ側で通す**。毎回切り替えると、次節の「記号の意味の違い」（`=` と `==` など）で混同が起きる

前提 — 問題文の表記が正
BASIC には処理系による方言がある。本ページに載せる BASIC は **JIS X 3003（Full BASIC）に近い基本形**に寄せてあるが、**細部は処理系で違う**（`LET` の有無、`DO … LOOP` の綴り、剰余が関数形か演算子形か等）。実際の問題文に印刷されたコードが本ページと違ったら、問題文の表記に従って読む。

## 7.最小限の文法対照表（BASIC ↔ C）

試験のプログラム読解に必要な文法はこの表の範囲でほぼ足りる。自分の言語の列だけ覚え、もう片方の列は「同じ意味の別表記」と確認できれば十分である。

| 項目 | BASIC | C | メモ |
| --- | --- | --- | --- |
| 変数の用意 | 宣言不要（使えばよい） | `int i, s;`（型を先に宣言） | C は整数 `int`・実数 `double` |
| 代入 | `LET S = 0` | `s = 0;` | C は文末の `;` が必須 |
| 等しい | `=`（IF の中の `A = B`） | `==` | 最重要の違い（下の罠） |
| 等しくない | `<>` | `!=` | 意味は同じ |
| 大小比較 | `< > <= >=` | `< > <= >=` | 両言語共通 |
| 論理演算 | `AND OR NOT` | `&& || !` | 「かつ・または・でない」 |
| 条件分岐 | `IF 条件 THEN … ELSE … END IF` | `if (条件) { … } else { … }` | 1行だけなら BASIC は `IF 条件 THEN 文` とも書く |
| 回数の繰り返し | `FOR I = 1 TO 5 … NEXT I` | `for (i = 1; i <= 5; i++) { … }` | `i++` は `i = i + 1` の略記。増分は `STEP 2` ↔ `i = i + 2` |
| 条件の繰り返し | `DO WHILE 条件 … LOOP` など 綴りは処理系差あり | `while (条件) { … }` | 条件が真の**間だけ**繰り返す。**条件が先頭なら0回もありうる／末尾（`do { … } while (条件);` 型）なら最低1回は動く**。綴りより「条件をどこで見るか」を読む |
| 配列の宣言 | `DIM A(5)` 開始番号は問題文のループで確認 | `int a[5];` → `a[0]`〜`a[4]` C は必ず 0 から | 開始番号が違う（下の罠2） |
| 配列の参照 | `A(I)`（丸かっこ） | `a[i]`（角かっこ） | かっこの形で言語を見分けられる |
| 余り（剰余） | `MOD(A, B)` など 関数形・演算子形の両方がある | `a % b` | A を B で割った余り |
| 出力 | `PRINT S` | `printf("%d\n", s);` | `%d` は整数の埋め込み位置 |
| コメント（注釈） | `REM 注釈` | `/* 注釈 */`（`// 注釈` も可） | 実行されない。読み飛ばしてよい |

罠1 — = と == の取り違え（最大の失点源）
BASIC の `=` は**文脈で意味が変わる**。`LET A = B` なら代入、`IF A = B THEN` の中なら「等しいか」の比較である。C はこれを記号で区別し、`=` は常に代入、`==` が比較。したがって C の `if` の中に `==` があったら「等しいか」と読む。「等しくない」も BASIC `<>` ↔ C `!=` で記号が違うだけで意味は同じ。
罠2 — 配列の添字が何番から始まるかを、覚えずに読み取る
C は **必ず 0 から**。`int a[5];` なら `a[0]`〜`a[4]` で、これは規格で決まっているので迷う余地がない。
BASIC 側は**本ページでは既定値を断定しない**。処理系や指定によって 0 開始にも 1 開始にもなり、その差は必ずコードのどこかに現れるからである。`FOR I = 1 TO 5` と書いてあれば添字は 1〜5、`FOR I = 0 TO 4` なら 0〜4。 既定値を暗記するより、**コードが実際に触っている添字を拾う**方が確実で速い。
**ただしループだけでは足りない。**見るのは**宣言・ループ範囲・添字式のすべて**である。 下のトレース例題2がまさにその形で、ループは `FOR I = 2 TO 5` なのに、 添字が 1 から始まると分かるのは**ループの前の `LET M = A(1)`** の方である。`A(I-1)` のような添字式やループ後の参照も同じように数える。
本Wikiは JIS X 3003 の規格原文を照合していないため、BASIC 側の既定の添字下限については断定を避けている。
罠3 — C の整数どうしの割り算は切り捨て
C で `int` どうしの `5 / 2` は **2**（小数点以下切り捨て）。これは C の規格で決まっている。割り算を含むトレースでは、**C 側は「整数どうしなら切り捨て」を1行ごとに意識する**。 BASIC 側が小数を保つかどうかは処理系差があるため本Wikiでは断定しない。割り算が出たら、問題文が示す途中経過や選択肢の値で、切り捨てかどうかを確かめる。

## 8.トレースの手順（変数表で機械的に実行する）

プログラム問題の解法の中心は**トレース（追跡）**である。プログラムを「読んで意味を悟る」のではなく、自分が計算機になったつもりで1行ずつ機械的に実行し、変数の値を表に記録する。
なぜ表に書くのか
頭の中だけでトレースすると、ループが2周目に入ったあたりで「今の I はいくつだったか」を必ず見失う。変数の値は**上書きされて消える**ので、紙の表に履歴として残すのが唯一確実な方法である。表さえ正しく埋まれば、プログラムの「意図」が分からなくても答えは出る。
手順は次の6ステップ。
1. プログラムに登場する**変数をすべて列挙**し、表の列にする（配列は要素ごとに列を分けるか、値の並びを欄外に書いておく）
2. ループより前の代入を実行し、**初期値の行**を書く
3. ループは**「周回」列**を作り、1周ごとに1行使う
4. 1文実行するたびに、**値が変わった変数だけ**新しい値を書く（変わらない変数は前の行の値のまま）
5. 条件判定（IF・ループ継続）は**真／偽を明記**し、どちらへ進んだかを矢印で書く
6. 出力文（PRINT／printf）に到達した**時点の値**が答え

条件 — ループの境界（回数）は表で確認する
「何回まわるか」を暗算で決めない。C の `i < 5`（`i = 0` 開始）は i = 0, 1, 2, 3, 4 の**5回**、`i <= 5`（`i = 1` 開始）も**5回**だが最後の i の値が違う。BASIC の `FOR I = 1 TO 5` も I = 1〜5 の5回。境界（未満か以下か）を1回分読み違える「1回ずれ」が定番の誤答なので、最初の1周と最後の1周は必ず表に書いて確かめる。
C の for が回る順番（規格で決まっている）
`for (A; B; C) { 本体 }` は**①A を1回だけ実行 → ②B を判定 → 真なら③本体 → ④C → ②へ戻る**。 B が偽になった瞬間に抜ける。だから `for (i = 1; i <= 5; i++)` を抜けた直後の`i` は **6**（最初に条件を満たさなかった値）で、これは C の規格で確定する。 BASIC の `NEXT I` を抜けた後の `I` も標準では同じ考え方だが、 処理系差の可能性があるので本Wikiでは断定しない。抜けた後の値が答えに絡む問題では、C 側で数える。

## 9.トレース例題（ループと配列）

前節の手順をそのまま使う。BASIC・C を併記するが、**自分の言語の側だけ読めばよい**。
例題1 — ループの和
**問:** 次のプログラムを実行したとき、出力される値を求めよ。
BASIC

```
LET S = 0
FOR I = 1 TO 5
  LET S = S + I
NEXT I
PRINT S
```

C

```
int i, s;
s = 0;
for (i = 1; i <= 5; i++) {
  s = s + i;
}
printf("%d\n", s);
```

解答とトレース開く前に、自分で変数表（I と S の2列）を埋めてみる
変数は I（ループカウンタ）と S（和）の2つ。初期値 S = 0 から、ループ本体 `S = S + I` を1周1行で記録する。

| 周回 | I | S = S + I の計算 | 実行後の S |
| --- | --- | --- | --- |
| 開始前 | — | （LET S = 0） | 0 |
| 1周目 | 1 | 0 + 1 | 1 |
| 2周目 | 2 | 1 + 2 | 3 |
| 3周目 | 3 | 3 + 3 | 6 |
| 4周目 | 4 | 6 + 4 | 10 |
| 5周目 | 5 | 10 + 5 | 15 |

I = 5 の周回を終えるとループ継続条件（BASIC: I が 5 以下 ／ C: `i <= 5`）が偽になって抜け、出力文に到達する。**答え: 15**（1 から 5 までの和）。
検算: $1+2+3+4+5 = \dfrac{5 \times 6}{2} = 15$。トレースの答えと一致する。
例題2 — 配列の最大値
**問:** 5個の値 30, 80, 50, 90, 20 がこの順で配列に入っている（BASIC では A(1)〜A(5)、C では a[0]〜a[4]）。次のプログラムを実行したとき、出力される値を求めよ。
BASIC

```
DIM A(5)
LET M = A(1)
FOR I = 2 TO 5
  IF A(I) > M THEN LET M = A(I)
NEXT I
PRINT M
```

C

```
int a[5] = {30, 80, 50, 90, 20};
int i, m;
m = a[0];
for (i = 1; i < 5; i++) {
  if (a[i] > m) {
    m = a[i];
  }
}
printf("%d\n", m);
```

解答とトレース開く前に、比較の真／偽を1周ずつ書いてみる
M（C では m）は「これまでに見た中の最大値」。先頭の要素を初期値にし、2番目以降と順に比較して、より大きければ入れ替える。**BASIC は I = 2〜5、C は i = 1〜4 と番号は違うが、参照する要素は同じ**（添字の開始が 1 と 0 で違うため。セクション7の罠2）。

| 周回 | BASIC: I ／ C: i | 見る要素と値 | M より大きいか | 実行後の M |
| --- | --- | --- | --- | --- |
| 開始前 | — | 先頭 = 30 | （M = 先頭で初期化） | 30 |
| 1周目 | I=2 ／ i=1 | 80 | 80 > 30 → 真 | 80 |
| 2周目 | I=3 ／ i=2 | 50 | 50 > 80 → 偽 | 80 |
| 3周目 | I=4 ／ i=3 | 90 | 90 > 80 → 真 | 90 |
| 4周目 | I=5 ／ i=4 | 20 | 20 > 90 → 偽 | 90 |

ループを抜けて出力。**答え: 90**（5個の中の最大値）。
不等号を `<` に変えれば同じ形で**最小値**になる（答えは 20）。比較の向きを1か所変えるだけで問題の意味が反転するので、トレースでは**不等号の向きを最初に確認**する。

## 10.フローチャートの記号

プログラムの代わりに**フローチャート（流れ図）**で処理が示されることもある。記号は次の対応で読む。読み方はプログラムと同じで、**矢印に沿って1記号ずつトレース**すればよい。

| 記号 | 名称 | 意味 | コードとの対応 |
| --- | --- | --- | --- |
|   | 端子 | 開始・終了 | プログラムの始めと終わり |
|   | 処理 | 計算・代入 | `LET S = S + I` ／ `s = s + i;` |
|   | 判断 | 条件で分岐（枝に Yes／No を書く） | `IF` ／ `if`、ループの継続判定 |
|   | 入出力（データ） | 値の入力・出力 | `PRINT` ／ `printf` |
|   | ループ端 | 繰り返しの範囲（開始と終了で上下対） | `FOR`〜`NEXT` ／ `for`。開始側に「I = 1, 5」のように範囲を書く |
|   | 流れ線 | 処理の順序 | 原則として上から下・左から右へ読む |

結論 — ループの書き方は2流儀あるが同じもの
繰り返しは、①**ループ端の対**で挟む書き方と、②**判断記号＋上へ戻る矢印**で書く書き方（while をそのまま図にした形）の2通りがある。どちらも意味は同じ。②では「戻る矢印がどこへ戻るか」と「抜ける条件はどちらの枝か」を最初に確認してからトレースを始める。

## 11.ビットとバイトの基礎

ビットは 0 か 1 の2値をとる情報の最小単位で、**1バイト = 8ビット**。10進↔2進↔16進の変換手順は本ページのセクション4（基数変換）を参照。ここでは**「n ビットで何通り表せるか」**というビット幅の視点だけ押さえる。
01
**n ビットで表せる状態の数**
$2^n \;\text{通り}$
1ビット増えるごとに2倍。4ビット = 16通り = 16進1桁、8ビット（1バイト）= 256通り、16ビット = 65536通り。$2^{10} = 1024$ が「キロ」の目安。

| ビット数 | 状態の数 | 0 起点の最大値 | 対応 |
| --- | --- | --- | --- |
| 4 | 16 | 15 | 16進1桁（0〜F） |
| 8 | 256 | 255 | 1バイト = 16進2桁（00〜FF） |
| 10 | 1024 | 1023 | 約10³（キロの目安） |
| 16 | 65536 | 65535 | 2バイト |

罠 — 「状態の数」と「最大値」を混同しない
「8ビットの最大値は 256」は誤り。8ビットで表せるのは $2^8 = 256$ **通り**だが、0 を含むので 0〜255、最大値は $2^8 - 1 = 255$。「$2^n$ は個数、最大値は $2^n - 1$」とセットで覚える。A/D 変換の量子化段階数（セクション3）の $2^n$ も同じ数え方である。
結論 — 2進数の桁シフトは 2倍・1/2倍
2進数を左へ1桁ずらすと値は **2倍**、右へ1桁ずらすと **1/2倍**（整数では小数点以下切り捨て）になる。10進数で桁をずらすと10倍・1/10倍になるのと同じ理屈で、**基数（その進数の底）倍**されるだけである。
