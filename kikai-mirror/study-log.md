### 判定の付け方

| 判定 | 意味 | 見分け方 |
| --- | --- | --- |
| ◎ | 解説を見ずに正解し、迷いがなく、理由を1行で言える。目安時間内 | 本番でそのまま取れる |
| ○ | ◎ の条件のうち目安時間内だけが欠けた | A問題で1問3分を超えた |
| △ | 正解したが、迷った／理由を言えない／同じ日の解き直しだった | 選択肢を絞る場面で手が止まった／「なぜその式か」を1行で言えない |
| × | 不正解、または正解でも解法が分からない | 解説を読んで初めて筋道が分かった |

4段が重ならないよう「正解したか」「迷ったか」「理由を言えるか」「時間内か」で切ってある。迷って正解したら ○ ではなく △。迷った正解は、放っておくと半分以上落ちるので、間違いと同じく復習に回す。 同じ記号を、確認問題・ひっかけ表・1分復習・節末の自己評価でも同じ意味で使う （時間を測らない部品では ○ を使わない）。

正解しても「なぜその式か」を1行で言えなければ △ に落とす。受験直後に「答えを覚えていて何とか解けた問題があった」という実感が残っており、 覚えているだけの正解を ○ にすると、この記録が使えなくなる。

### 次に解き直す日はどう決まるか

間違えた直後に解き直すと、覚えているから解けてしまう。それは定着ではない。 少し忘れた頃に思い出して初めて記憶に残るので、次回の日付は忘却曲線から算出する。 固定日数ではなく、判定と過去の履歴で伸び縮みする。 各単元の確認問題・ひっかけ表・1分復習も同じ忘却曲線で次回日を持ち、期限が来たものはホームの「今日やる（Wiki 内）」に単元ごとに出る（1日の上限はこの過去問グリッドだけに掛ける）。

| 判定を続けたとき | 次回までの間隔（日） |
| --- | --- |
| ◎ を重ねる | 8 → 66 → 365 |
| ○ を重ねる | 2 → 11 → 46 → 163 → 365 |
| △ → △ → ○ → ◎ | 1 → 3 → 9 → 36 |
| × を付ける | それまでの深さで変わる。新しい問題・△ の多い問題は 1、○ を2回なら 2、◎◎× なら 4、◎◎◎× なら 7（どれも振り出しより短く戻る） |

表の数値は予定日ちょうどに解き直した場合。早く解けば短く、遅れれば長くなる。 いずれも締切で頭打ちになるので、上の 365 日などは実際には出ない。

ただし締切（2027-03-07＝試験日 2027-03-21 の 14 日前）を越えては寝かせない。FSRS は「いつまでに」の制約が無い前提の設計なので、 ◎ を重ねると 365日後＝試験のはるか後ろへ送ってしまう。そこで次回日は締切までに収める（締切を過ぎた判定は試験日までに収める）。 さらに1日に予定できるのは 10 マスまでで、その日が埋まっていれば1日ずつ前倒しして空いた日に置く。 試験の直前に全マスがまとめて来るのを防ぐためで、締切までに埋まり切らない分は、締切から試験の前日までの間に同じ規則で並べる。そこにも入り切らない分は試験日へは送らず、その間で最も空いている日に上限を超えて置く（最後の2週間は1日の量が増えることがある）。

◎○ も再挑戦の対象にしてある。間隔が長いだけで、期限が来れば「今日やる」に出る。 試験前に「○ にはなっているが半年触っていない」を拾うためで、鮮度の落ちた ○ は ○ のままとは限らない。

計算は scripts/fsrs_engine.py（py-fsrs から逐語移植した FSRS-6）の JS 移植で、records.json 側のスケジューラと同じ式・同じ定数を使う。別式にすると同じ問題に 2つの再挑戦日が出るため。数値が一致することは機械照合している。

### 別の端末へ記録を持ち運ぶ

◎○△×・忘却曲線の日付・節の理解度・確認問題の結果は、すべてそのブラウザの中だけに保存される。 PC で付けた記録は iPhone には出てこないし、その逆も同じである。同期サーバは持たない方針なので、JSON を人が運ぶ経路を用意してある。使い方
- 記録がある側の端末でこのページを開き、「JSONファイルとして保存」か「クリップボードへコピー」
- 移す先の端末でこのページを開き、ファイルを選ぶか欄に貼り付けて「内容を確認」
- 件数と差分を確かめてから「マージして取り込む」。ここを押すまで何も書き込まれないこの端末の記録: 過去問 0 マス ／ 節の理解度 0 件 ／ 確認問題 0 件 ／ ひっかけ 0 件 ／ 1分復習 0 件 ／ 誤答カード 0 件（保存キー 0 個）JSONファイルとして保存クリップボードへコピー別の端末の記録を読み込む貼り付けた内容を確認ブラウザの記録は消えることがある

プライベートブラウズ、サイトデータの削除、別ブラウザへの乗り換えで記録は消える。定期的に「JSONファイルとして保存」で控えを取っておくこと。 読み込みは既定がマージ（既存を消さない）で、「すべて置き換える」は二度押しを要求する。
