# 学習記録（過去問トラッカー）

解いた過去問と、間違えた日を残す。面（どこまで解いたか）はここ、質（なぜ間違えたか）はチャット経由の学習ログ。単元ごとではなく機械まるごと1枚で管理する。

## 1.過去問の進捗

解いた問のマスをタップして **◎○△×** を残す。マスは**1問＝1マス**で、 B問題（問15〜18）だけ (a)(b) に分かれている。単元は問わない（R3 問15 は1つの問題なので、 単元ごとに同じマスを持つと二重管理になる）。
**過去問集の進捗（機械）**記録 0 マス（◎○ 0 ／ △× 0）まず1問。解いた年度回の行をタップ
解いた問のマスをタップすると **◎ → ○ → △ → × → 空** と変わり、**その日の日付も一緒に残る**。**判定を上げたいとき**（△ → ○ など）は空まで回して付け直す。途中で一度マスが消えるが、**その日のうちなら履歴は残る**ので間隔は振り出しに戻らない。 タップするとマスの下に**1行メモ**が出る。△× なら「なぜ落としたか」を、◎○ なら「なぜその式か」を書く。**正解しても「なぜその式か」を1行で言えなければ「言えない → △」で △** に落とす（覚えていただけの正解を弾くため）。**問15〜18 は B問題**なので (a)(b) を別マスにしてある。解いていない問は空のままでよい （年度により B問題の構成が違う。問17・18 は選択）。
次に解き直す日は**忘却曲線から算出**する（判定が良いほど長く空く）。 期限が来たマスは**枠が光って**「今日やる」に出る。**◎○ も対象**で、間隔が長いだけ——「○ だが半年触っていない」も期限が来れば出てくる。 間違えた直後に解き直しても、覚えているだけで解けてしまい定着しない。

## 2.この記録の回し方

面と質を分けているのは、片方だけでは学習が回らないから。**どこまで解いたか**は端末で軽く残し、**なぜ間違えたか**は端末に閉じない場所に残す。

| 残すもの | どこに | なぜそこか |
| --- | --- | --- |
| 解けた／解けない（◎○△×と日付） | このページのグリッド | 大量・高頻度・タップ1回。消えても解き直せば復元できる |
| 理解できなかったところ・公式・考え方・計算ミス・覚えたいこと | チャットに書く → 学習ログに追記 | 端末をまたいで読め、傾向も集計できる。**消えたら再現できない資産** |

### 判定の付け方

| 判定 | 意味 | 見分け方 |
| --- | --- | --- |
| **◎** | 解説を見ずに正解し、**解法と理由を説明できる** | 人に教えられる |
| **○** | 正解した。ただし**少し迷った** | 選択肢を絞る場面で手が止まった |
| **△** | 正解したが**勘・公式の選び方・理解に不安がある** | 「なぜその式か」を1行で言えない／時間超過 |
| **×** | **不正解**、または正解でも**解法が分からない** | 解説を読んで初めて筋道が分かった |

4段が重ならないよう「**正解したか**」と「**理由を言えるか**」の2軸で切ってある。 正解したかだけで付けると ◎ と ○ の区別が消え、記録が「解いた／解いていない」の2値に退化する。
**正解しても「なぜその式か」を1行で言えなければ △ に落とす。**受験直後に「答えを覚えていて何とか解けた問題があった」という実感が残っており、 覚えているだけの正解を ○ にすると、この記録が使えなくなる。

### 次に解き直す日はどう決まるか

間違えた直後に解き直すと、**覚えているから解けてしまう**。それは定着ではない。 少し忘れた頃に思い出して初めて記憶に残るので、**次回の日付は忘却曲線から算出**する。 固定日数ではなく、判定と過去の履歴で伸び縮みする。

| 判定を続けたとき | 次回までの間隔（日） |
| --- | --- |
| ◎ を重ねる | 8 → 66 → 365 |
| ○ を重ねる | 2 → 11 → 46 → 163 → 365 |
| △ → △ → ○ → ◎ | 1 → 3 → 9 → 36 |
| × を付ける | 1（振り出しに戻る） |

表の数値は**予定日ちょうどに解き直した場合**。早く解けば短く、遅れれば長くなる。 いずれも**試験日で頭打ち**になるので、上の 365 日などは実際には出ない。
**ただし試験日を越えては寝かせない（2027-02-04 を想定）。**FSRS は「いつまでに」の制約が無い前提の設計なので、 ◎ を重ねると 365日後＝試験のはるか後ろへ送ってしまう。そこで**間隔は試験日までの残り日数で頭打ち**にしてある。残りが減るほど間隔も縮み、 直前期には全マスが一巡する。
**◎○ も再挑戦の対象**にしてある。間隔が長いだけで、期限が来れば「今日やる」に出る。 試験前に「○ にはなっているが半年触っていない」を拾うためで、**鮮度の落ちた ○ は ○ のままとは限らない**。
計算は `scripts/fsrs_engine.py`（py-fsrs から逐語移植した FSRS-6）の JS 移植で、`records.json` 側のスケジューラと同じ式・同じ定数を使う。別式にすると同じ問題に 2つの再挑戦日が出るため。数値が一致することは機械照合している。

### 学習ログへの渡し方

グリッドのコピーボタンを押すと、**今日解いた分**と**予定日が来た分**の一覧が クリップボードに入る（寝かせ中は入らない。数百行になって貼らなくなるため）。 各行には `exam= / q= / result= / date=` が付いているので、**あとは「なぜ間違えたか」を書き足すだけ**でよい。体裁は整えなくてよい。
コピーは**解いて判定を付けたあと**に押す（付ける前に押すと、その日の分が入らない）。
書籍の問題文は転載しない。残すのは年度・問番号と、自分の理解だけ。

### 単元との紐付け（構造のみ・現在は未登録）

年度 × 問番号の表だけだと「**%Z の過去問だけ**」「**変圧器で △× だけ**」を取り出せない。 1問ごとに単元を持たせる台帳（`KAKOMON_TOPICS`）を用意してあるが、**中身は空のまま出している**。
なぜ空で出すのか
年度と問番号から単元を推測して埋めることはできる。だがそれをやると、 分類を間違えたときに**「この単元は解き終えた」という誤った達成感**が生まれ、 本来やるべき復習が抜ける。空欄のほうが害が小さいので、**実物を確認した問だけを1件ずつ登録する**方針にした。
1件はこの形で持つ。B問題は `cell` を `"15a"` / `"15b"` に分ける。

| 項目 | 意味 | 例 |
| --- | --- | --- |
| `session` | 年度回（グリッドの行と同じ） | `"R8上"` |
| `cell` | 問番号。B問題は小問まで | `"3"` / `"15a"` |
| `topic` | Wikiのページ id | `"transformer"` |
| `subtopic` | そのページの節 id（省略可） | `"pz"` |
| `difficulty` | 体感難易度 1〜3（省略可） | `2` |
| `source` | 出典（年度・期・科目まで） | `"令和8年度上期 第三種電気主任技術者試験 機械科目"` |

登録済み **0 件**。解いた問について「この問題は変圧器の %Z だった」とチャットで伝えてもらえれば、 こちらで1件ずつ追記する。埋まった時点で単元別・節別の抽出を出す。
